- Deploys now guard the SiteGround inode cap. A pre-flight before the backup and upload counts the whole account with `du --inodes -s -x "$HOME"`, adds the `RW_INODE_EXTERNAL` repo variable for usage outside that account, warns at 450,000 and aborts at 540,000 of 600,000. Rollback and backup are never blocked, and the deploy repeats the check before it extracts anything.
- A failed deploy or failed upload no longer leaves an archive in `incoming`. Release pruning only removes 40-character sha directories under `releases` and does nothing when `current` cannot be resolved. At most two database dumps are kept, including when a backup is skipped.
- A daily `host:prune-files` scheduler task removes stale sessions, views, file cache and logs. Production logs use the `daily` channel with a 7 day limit (`LOG_DAILY_DAYS`, which now reaches the `days` setting Laravel reads).
- The Deploy workflow has a manual `maintenance` action (with a `prune` switch) that reports real-path inode counts per release and prunes to the current release plus one rollback, without deploying, migrating, or reading `demo-logins.txt` or `platform-admin.txt`.
