- Scheduling a departure and cancelling one accept an idempotency key. `POST /api/v1/departures` with the same key and the same service, start, end, private flag, and seats returns the first departure and does not write a second `departure.scheduled` audit. A different schedule for that key is refused. `POST /api/v1/departures/{departure}/cancel` with the same key returns the first cancellation and does not write a second `departure.cancelled` audit. The same key on another departure in this workspace is refused, and that departure stays scheduled. A key longer than 80 characters is refused and stores nothing. A key of 80 characters is kept. The header key wins over a key in the body. A schedule with no key still creates a departure each time. A second cancel with no key is refused and stores nothing. A departure that still has a booking stays scheduled, and that refusal does not keep the key. A service that is not a tour does not keep the key. Another workspace is not found. The price, payments, refunds, taxes, and fees stay as they were. Spec Section 13.
