- Quoting a booking accepts an idempotency key. `POST /api/v1/bookings/{booking}/pricing` with the same key and the same channel, tax, promo, deposit, and add-ons returns the first quote and does not write a second price snapshot. A different request for that key is refused, and the stored quote stays as it was. A key longer than 80 characters is refused and stores nothing. A key of 80 characters is kept. An unknown promo code does not use up the key. The header key wins over a key in the body. A request with no key still keeps the first snapshot and writes no retry row. The same key on another booking in this workspace is refused, and that booking is not quoted. Another workspace is not found and does not use the key. The price rules, payments, refunds, taxes, and fees stay as they were. Spec Section 13.
