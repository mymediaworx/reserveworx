- Issuing a refund accepts an idempotency key. `POST /api/v1/bookings/{booking}/refunds` with the same key and the same reason, subtotal, and tax returns the first refund and does not call Stripe again. A different reason, subtotal, or tax for that key is refused, and the same key on another booking in this workspace is refused. A key longer than 80 characters is refused and stores nothing. A key of 80 characters is kept. The header key wins over a key in the body. A request missing a reason, naming a reason that is not a refund, or naming a dispute does not use up the key. A request with no key still refunds each time. Another workspace is not found and does not use the key. A refund stored before this column has an empty hash and still returns the first refund. Migration `2026_10_27_113012` adds nullable `refunds.payload_hash` and does not change any other column. The price, payments, taxes, fees, and the refund amounts in Section 7.7 stay as they were.
